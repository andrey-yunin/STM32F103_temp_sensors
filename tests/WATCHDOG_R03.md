## Сборка

Из корня STM32F103_temp_sensors:

```bash
python3 tests/check_watchdog_hooks.py
python3 tests/build_watchdog.py
python3 tests/build_watchdog.py --production
```

Тестовый образ: `WatchdogTest/STM32F103_temp_sensors.elf` (также .hex и .bin).
Обычный образ для возврата: `ProductionCheck/STM32F103_temp_sensors.elf`.
BIN загружается по адресу 0x08000000. При прошивке сохранить страницу
конфигурации, не выполнять полное стирание Flash.

Скрипт использует makefiles из Debug, пересобирает все объекты в отдельной
директории. Только WatchdogTest получает `APP_WATCHDOG_TEST_HOOKS=1`.
Обычная сборка CubeIDE Debug оставляет хуки выключенными; запуск обычной
Debug-конфигурации не загружает автоматически WatchdogTest.

## Команды

Studio закрыть. Сначала запустить запись в отдельном терминале:

```bash
candump -t A -x can0 | tee ~/thermo_watchdog_r03.log
```

После загрузки тестового образа запросить его маркер и причину последнего reset:

```bash
cansend can0 00401000#FDF0000000000000
```

Ответ: ACK, DATA `02 80 01 01 xx xx xx xx`, DONE. Первые два байта
полезной нагрузки — версия тестового формата 1 и включённые хуки 1.
Последние четыре байта — RCC_CSR little-endian, сохранённый при старте
supervisor. Затем sticky reset flags очищаются только в тестовой сборке.
После IWDG reset должен быть установлен бит 29 (`CSR & 0x20000000`).
Первый ответ после прошивки может содержать более старые причины сброса.

Выбирать **одну** команду, затем проверять восстановление до следующей:

| Сценарий | Команда |
|---|---|
| 1: CAN перестаёт продвигаться, отдаёт CPU | `cansend can0 00401000#FEF001EFBE000000` |
| 2: Dispatcher перестаёт продвигаться, отдаёт CPU | `cansend can0 00401000#FEF002EFBE000000` |
| 3: Temp Monitor перестаёт продвигаться, отдаёт CPU | `cansend can0 00401000#FEF003EFBE000000` |
| 4: CAN busy-loop, без osDelay/yield | `cansend can0 00401000#FEF004EFBE000000` |

F0FE использует sensor_id как номер режима, ключ BEEF в параметрах.
Неверный ключ даёт ACK + NACK INVALID_KEY; режим вне 1–4 —
ACK + NACK INVALID_PARAM. При правильной команде DONE отсутствует.
После постановки ACK оставлено окно 100 тиков для отправки, затем хук
останавливает выбранную задачу на следующей точке heartbeat, до инкремента.
Окно отправки не гарантирует доставку ACK. Хук сбрасывается при reset,
Flash и карта датчиков не изменяются командами теста.

После каждого сценария выждать 10 секунд и запросить:

```bash
cansend can0 00401000#FDF0000000000000
sleep 1
cansend can0 00401000#01F0000000000000
sleep 1
cansend can0 00401000#1090000000000000
```

Ожидаются IWDGRSTF, полный ответ F001 и восстановление температур 0–3.
Если плата не отвечает, сохранить лог и выяснить причину, следующий сценарий
не запускать. Эти команды лишь проверяют восстановление; они не доказывают
выполнение safe-state до reset.

## Полный критерий R03

Нужно отдельно наблюдать отпускание 1-Wire до reset и отсутствие новых
операций до перезапуска. При инструментальной проверке доступны символы
`app_watchdog_test_entered` (режим входа в хук) и
`app_watchdog_test_failed_mask` (бит 0 CAN, 1 Dispatcher, 2 Temp Monitor).
В busy-loop могут остановиться и менее приоритетные задачи: маска может
содержать несколько битов. Supervisor должен попасть в Error_Handler,
который запрещает IRQ и вызывает AppSafety_EnterSafeState.
Переменные очищаются при reset; они предназначены для отладчика,
не являются сохранённым журналом. Остановка CPU сама по себе не доказывает
штатный переход в safe-state. Временные измерения выполнять без остановки CPU.
